# 轻记 AI 产品竞争力实施计划

状态：三阶段候选实现完成，进入跨平台发布验收
基线：`1.0.7` / schema v14
产品定位：无需账号、账单默认不出设备、智能结果可检查可修改可撤回的中文个人账本。

当前进度（2026-08-14）：P1–P3 的代码、迁移、用户入口与自动化测试均已落地。包括删除全部、CSV、加密备份/原子恢复、系统隐私锁与金额保护、首次引导；CSV/TSV/XLSX 与微信/支付宝导入、批量审核/去重/撤销、分享/OCR/快捷入口、周期模板；字段级解释、本地学习治理、风险分级、自动确认审计、本地洞察与最小化产品价值指标。随后补齐了月度总预算/分类预算和就地新建分类/账户。完整 JS/数据库门禁和 Android Debug 原生构建通过。剩余工作是 Android/iOS 真机往返验收、macOS Xcode Archive、真实生产签名与大数据量性能基线，不再是功能“尚未实现”。

本文是三阶段产品工作的执行与验收基线。功能完成必须同时具备代码、自动化测试、数据迁移/回滚说明、跨平台边界和用户可见入口；只有页面或只有底层接口不算完成。

## 共同产品原则

1. 默认本地：账单明细、原文、学习规则和模型输入默认不发送到开发者服务器。
2. 用户控制：高风险或有歧义的结果不得静默入账；导入、恢复、删除和联网能力必须明确确认。
3. 数据可带走：用户可以导出可读数据，也可以创建可完整恢复的版本化备份。
4. 数据不轻易丢失：破坏性操作提供范围说明、二次确认和失败原子回滚。
5. 输入共用一套账本语义：手动、文字、语音、分享、OCR、文件和通知最终进入相同的验证、去重、确认与写入边界。
6. 小团队取舍：不以多账本、家庭协作、投资组合或云端大模型的功能数量追赶综合型竞品。

## 阶段一：信任闭环

目标：让用户敢把长期账本留在本机，并能安全迁移、恢复和彻底清除。

### P1.1 数据生命周期控制

- 增加账本数据概览，显示已确认、待确认、回收站、规则和反馈数量。
- “删除全部数据”覆盖交易、回收站、待确认、标签关联、项目、标签、商户、预算、导入记录、规则、学习反馈、抑制记录、语音幂等回执和个性化设置。
- 系统分类与默认账户恢复为可用初始状态；删除在单个 SQLite 事务内完成。
- 删除前展示明确范围并要求用户输入确认短语；失败时不得留下部分删除状态。
- 自动化测试包含成功、外键、失败回滚和删除后重新记账。

### P1.2 可读导出

- 导出 UTF-8 CSV，字段至少包含交易 ID、时间、类型、金额（整数分与展示值）、币种、分类、账户、商户、项目、标签、备注、来源、确认状态、删除状态和更新时间。
- 支持是否包含回收站与原始文字；默认不包含原始文字。
- 使用系统文件保存面板，不申请泛化存储权限；取消不视为错误。
- CSV 公式注入字符必须转义，金额不得经过浮点计算。

### P1.3 加密备份与原子恢复

- 备份格式包含格式版本、schema 版本、创建时间、应用版本、表清单、记录数和完整性校验。
- 备份正文使用用户口令派生密钥加密；口令和派生密钥不得写入日志、SQLite 或偏好设置。
- 使用平台安全随机数、PBKDF2-HMAC-SHA256 和 AES-256-GCM；格式记录算法参数以支持升级。
- 恢复先完成文件大小限制、格式、算法、口令认证、校验、schema 兼容性和外键验证，再以单事务替换数据。
- 失败、取消或错误口令保留原账本；成功后重新打开数据库并刷新全部页面。
- Android/iOS 使用系统文档选择器；外部备份文件只能由用户主动删除。

### P1.4 隐私锁与展示保护

- 支持系统生物识别/设备凭据解锁；不自行保存可逆 PIN。
- 用户启用、恢复前和关闭隐私锁时都需要一次平台身份验证。
- 冷启动及超过可配置后台宽限期后锁定；系统能力变化时安全降级为锁定状态。
- 支持全局隐藏首页、分析和流水金额；隐藏状态不得改变统计或导出内容。
- 截图/最近任务保护：Android 启用安全窗口；iOS 在后台快照上覆盖隐私层。

### P1.5 首次体验与恢复提示

- 首次启动用不超过三屏说明“本地保存、智能需确认、备份责任”。
- 用户可以跳过示例数据；默认账户可直接使用。
- 在形成第一笔确认交易后提醒创建备份，但不强制注册或联网。
- 初始化、崩溃恢复、数据库升级和空状态均有可操作错误信息。

### 阶段一完成证据

- 所有单元/集成/UI 合同测试通过。
- Android Internal 真机完成导出、错误口令、恢复、删除、后台锁定和进程重启回归。
- iOS 在 macOS 完成编译及相同生命周期回归。
- `SECURITY_THREAT_MODEL.md`、`REQUIREMENTS_TRACEABILITY.md` 和 `RELEASE_RUNBOOK.md` 对应阻断项有直接证据后才能关闭。

## 阶段二：采用与迁移

目标：让已有账本用户可以低风险迁入，并让日常记录不必先打开 App。

### P2.1 通用导入管线

- 实现版本化 importer DTO，所有适配器只解析来源，不执行 SQL。
- 支持通用 CSV/XLSX 字段映射、编码/日期/金额预览和映射模板。
- 支持微信与支付宝官方导出文件；解析器使用脱敏夹具和格式版本合同测试。
- 导入先预览、再批量审核、最后通过统一写入边界提交。

### P2.2 批量审核与去重

- 指纹综合来源 ID、时间窗口、整数金额、方向、账户和标准化商户。
- 明确区分“确定重复”“疑似重复”“非重复”，不得自动删除原账。
- 支持批量改分类/账户、忽略、确认和撤销本次导入。
- 导入记录保存统计和哈希，不默认保存完整原始文件。

### P2.3 分享、截图与 OCR

- Android Share Intent 与 iOS Share Extension 接受文字和用户主动选择的图片。
- OCR 首选平台本地能力；任何联网 OCR 都需单独说明并逐次授权。
- 图片仅在解析期间使用，默认不写入账本或缓存；结果进入同一候选确认管线。
- 支持支付截图批量候选、逐条确认和重复提醒。

### P2.4 快捷入口

- Android 快捷方式/通知栏快捷动作与 iOS Shortcut/Widget 打开指定记账模式。
- 深链参数只允许预填，不允许绕过确认和写入验证。
- 周期记账支持草稿提醒或用户选择的自动入账策略；默认需要确认。

### 阶段二完成证据

- 各来源黄金夹具、畸形文件、超大文件、公式注入、重复导入和原子回滚测试通过。
- 主流 Android ROM 与 iOS 分享入口真机验证。
- 从至少两款主流记账产品迁入样本后，金额总和、笔数和抽样字段可对账。

## 阶段三：可信智能差异化

目标：不靠云端窥探账本，也能持续降低修正成本并给出可行动的财务提醒。

### P3.1 可解释识别

- 候选展示金额、类型、分类、账户和时间分别来自哪段证据或哪条规则。
- 规则、商户历史、显式用户输入和语义推断有固定优先级。
- 无法解释的建议不得标记为高置信度。

### P3.2 本地学习治理

- 延续三次可靠纠正晋级，并增加规则冲突预览、命中历史和一键撤销学习。
- 用户可导出、停用和彻底删除学习数据。
- 对联系人、综合平台和稀疏样本继续禁止过度学习。

### P3.3 风险分级与自动化策略

- 金额歧义、转账/借贷、异常大额、账户缺失、时间冲突和疑似重复强制确认。
- 只有用户明确开启且满足可解释、高置信、非高风险、可撤销条件的来源才允许自动确认。
- 每笔自动确认保留原因和操作回执，并提供短期撤销入口。

### P3.4 本地财务洞察

- 基于确认账目提供预算偏离、分类连续上涨、异常大额、重复订阅候选和安全可花额度。
- 所有计算可追溯到具体账目和统计口径；不使用恐吓式文案或伪造预测精度。
- 洞察默认本地计算，可关闭、可解释、可跳转处理。

### 阶段三完成证据

- 建立脱敏中文表达、歧义、风险和回归数据集，分别报告字段级准确率，不只报告整体成功率。
- A/B 验证首笔成功率、平均确认操作数、七日有效记账天数和纠正率；不以功能点击量替代用户价值。
- 隐私清单证明智能模块没有新增未声明的数据出站路径。

## 实施顺序与依赖

1. 数据生命周期服务与删除全部（后续恢复测试需要可靠清场）。
2. 版本化明文快照核心、CSV 序列化和完整性校验。
3. 平台文件门户与原生加密模块。
4. 设置页的数据管理、恢复协调和应用重载。
5. 隐私锁、金额隐藏、首次体验。
6. importer DTO、通用 CSV，再做微信/支付宝适配器。
7. 批量审核/去重，再接分享与 OCR，最后接系统快捷入口。
8. 可解释证据贯穿解析管线，再扩展学习治理、风险策略和洞察。
9. 每个阶段末执行完整质量门禁与真机矩阵，不把实验构建结论外推到生产构建。

## 明确非目标

- 第一轮不做开发者托管的账号云和多端实时同步。
- 第一轮不做家庭协作、生意进销存、投资组合或多币种汇率服务。
- 不允许为了“全自动”而默认申请 Android 无障碍权限、保存支付截图或绕过用户确认。
- 不把未完成真机基准的离线语音模型作为核心获客承诺。
