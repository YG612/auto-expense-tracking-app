# 轻记 AI 工程交付流程

本文定义从需求到发布的最小工程闭环。它约束开发方式，不增加
`PRD.md` 第一版之外的产品功能。

## 1. 基本原则

- 权威需求、数据模型、验收用例和阶段边界先于代码。
- 交易金额、类型、分类、账户、确认状态和去重属于领域不变量，不由页面各自解释。
- 平台原生层只提供最小能力，交易语义和写入策略保持跨平台一致。
- 默认本地、最少权限、最少保留；生产密钥永不进入仓库或移动端配置。
- 一项阶段功能“已编码”不等于第一版“可生产发布”。发布还需要安全、隐私、迁移、设备、签名和回滚门禁。
- 线上缺陷优先修正错误模型、状态机或写入边界，不按机型堆叠临时分支。

## 2. 从需求到运行的八道门

### Gate 1：需求与范围

每项工作必须关联一个需求 ID 和至少一个验收场景。PRD 未授权的账号、云同步、广告、破解支付平台或后台采集不得混入当前版本。

必须回答：

1. 用户结果是什么；
2. 哪些数据会被读取、保存、传输和删除；
3. 失败时是否可能错账、重复记账、丢账或泄露；
4. Android 与 iOS 的能力差异是什么；
5. 如何自动验证和真机验证。

### Gate 2：架构与数据决策

涉及新入口、数据库结构、权限、第三方依赖或跨平台差异时，先写简短 ADR。ADR 至少记录候选方案、选择理由、失败模式、迁移和撤销方式。

页面不能执行 SQL。手动、文字、语音及后续导入来源必须进入同一交易写入用例，由它完成语义校验、幂等、数据库事务和学习反馈。

### Gate 3：威胁与隐私评审

按 [SECURITY_THREAT_MODEL.md](SECURITY_THREAT_MODEL.md) 检查本地攻击、恶意输入、供应链、错误日志、权限、备份、导出和数据删除。新增数据处理必须更新数据生命周期表。

### Gate 4：实现与测试

采用小批量纵向切片：先写领域契约和失败用例，再实现 repository/use-case，最后接 UI 和原生层。每个切片必须包括：

- 正常路径；
- 边界和畸形输入；
- 重复点击、并发和进程中断；
- 写入失败及事务回滚；
- Android/iOS 能力不可用时的可解释降级；
- 不保存、不上传和删除策略。

### Gate 5：合并前质量门禁

Pull Request 必须通过：

```text
pnpm install --frozen-lockfile
pnpm release:identity:test
pnpm release:identity:check
pnpm migration:integrity:test
pnpm migration:integrity:check
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test:ci
Android JVM tests + isolated internal assemble
```

涉及 iOS 原生代码时还必须在 macOS 完成 simulator build。Windows 静态检查不能替代 Xcode 编译。

至少一名未参与实现的人审查领域不变量、数据迁移、权限和失败路径。自动测试全绿不能覆盖代码审查失败。

### Gate 6：内部版本

内部 Android 包使用与生产不同的 application ID。测试人员按照设备矩阵验证安装、升级、冷启动、离线、权限拒绝、低存储、系统语音缺失、进程被杀和大字体。

内部包不得使用生产身份配合公开 Debug 私钥。内部验证结果记录设备、系统版本、App build、步骤和截图，不使用“朋友说可以”替代证据。

### Gate 7：生产候选与发布

执行 [RELEASE_RUNBOOK.md](RELEASE_RUNBOOK.md)。生产候选必须使用外部私有签名、单调递增 build、真实设备升级测试、数据库兼容矩阵、依赖清单和制品哈希。

### Gate 8：运行、回滚与复盘

当前版本不接入第三方遥测。出现问题时使用稳定错误码和不含账目正文的诊断证据。生产故障采用更高 build 的前向修复，不发布会破坏新 schema 的旧二进制。严重缺陷完成根因分析、回归测试和威胁模型更新。

## 3. 优先级

- **P0**：可能导致错账、丢账、隐私泄露、恶意升级、生产不可回滚或门禁虚假通过；阻止合并或发布。
- **P1**：在常见设备、辅助功能、大数据量或维护周期中造成明显风险；进入下一质量迭代。
- **P2**：体验、一致性和开发效率改善，不得抢占 P0。

## 4. 完成定义

功能完成需要需求、代码、测试和文档一致。第一版生产就绪还额外要求：

- PRD 第一版所有必需项闭环；
- 隐私锁、原始文本策略、导出、备份恢复和删除全部数据通过验收；
- Android 与 iOS 生产签名、包身份和升级路径完成验证；
- N-1 数据库升级、低存储、崩溃恢复和大数据量门禁通过；
- 发布清单中没有未豁免的 P0。

任何豁免必须包含负责人、风险、截止时间和退出条件，不能只写“后续处理”。
