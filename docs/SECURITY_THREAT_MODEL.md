# 轻记 AI 安全与隐私威胁模型

状态：工程威胁模型，不是法律意见或安全认证。范围覆盖当前本地优先第一版、阶段 1–7，以及阶段 8 的 Android 支付通知候选实现；云同步或联网 AI 服务必须另行增量评审。

## 1. 保护目标与资产

优先保护：

- 交易金额、类型、分类、账户、商户、备注、项目和时间；
- 语音转写和文字记账原文；
- 用户纠正、个性化规则和分类反馈；
- SQLite 数据库、回收站、未来备份和导出文件；
- App 包身份、生产签名私钥、版本和迁移历史；
- 权限选择和“允许系统联网转写”等明确同意状态。

安全目标是“不被替换、不被篡改、不重复、不静默丢失、不过度保留、不在错误或日志中泄露”。

## 2. 攻击者与失效来源

- 诱导测试用户安装伪造升级包的人；
- 获得已解锁设备、调试备份、导出文件或截图的人；
- 提交超长文本、畸形日期、重复请求、并发点击或恶意规则的本地输入者；
- 出错或恶意的依赖、构建 Action、语音服务和未来第三方 SDK；
- 把数据库错误、路径、SQL、转写正文写入日志或用户界面的开发失误；
- 修改旧 migration、发布低 build、错误签名或错误包名的发布操作；
- 低存储、进程被杀、数据库损坏、OEM 回调缺失等非恶意故障。

不承诺抵御能够完整控制 root/jailbreak 设备并读取进程内存的攻击者，但仍应最小化可提取数据和后续影响。

## 3. 信任边界

```text
用户输入
  -> React Native UI（不可信文本）
  -> 领域解析/交易写入用例（语义与幂等边界）
  -> repository（参数化存储）
  -> SQLite / OS 应用沙箱

系统语音服务
  -> Kotlin/Swift 最小 DTO
  -> 共享文字解析

开发源代码
  -> CI/依赖/构建工具
  -> 内部测试包（隔离 ID）
  -> 生产签名服务（仓库外秘密）
  -> 生产制品
```

原生层不得直接生成或保存交易；页面和未来通知/import adapter 不得绕过统一交易写入边界。

## 5. 重点攻击路径

### 5.1 公开 Debug 私钥替换生产候选

历史测试包曾让 `com.qingjiai` Release 使用仓库内公开 Debug 私钥。攻击者可构建同包名且同签名的恶意 APK；用户手动安装时，Android 会把它视为可升级包，恶意代码可在相同 App 沙箱上下文中读取账本。

当前控制：Debug 使用 `com.qingjiai.debug`，内部包使用 `com.qingjiai.internal`；生产 Release 只能引用 CI/签名机 secret，且 `pnpm release:identity:check` 拒绝 `signingConfigs.debug`、身份漂移与硬编码密钥。已经安装的 Debug 签名生产 ID 不能原地切换到新签名，测试期应尽早清理该身份。此控制只有在 CI 门禁、真实证书指纹和升级验证都有证据后才算发布闭环。

### 5.2 入口各自校验造成脏账

如果页面、文字、语音、通知和导入分别校验，新增入口可能写出“收入 + 支出分类”“转账 + 消费分类”等组合。数据库单列 CHECK 不能表达所有跨表语义。

控制：所有来源使用同一个 `TransactionWriteService` 或等价用例；它在事务前验证领域不变量，在事务内执行交易、标签、反馈和幂等写入。repository 是存储细节，不是公开业务写入口。

### 5.3 敏感原文通过保留或错误泄露

文字/转写可能包含工资、医疗、关系、位置等高敏上下文。即便不上传，永久保存、系统备份、截图错误或诊断导出仍可泄露。

控制：默认不保存不必要原文；设置必须作用于统一写边界并可清除历史。UI 只展示安全错误码，诊断仅使用事件类别、版本、平台和阶段，不含金额、商户、备注、原文、SQL 参数或数据库路径。

### 5.4 migration 篡改和危险回退

修改已经发布的 migration 会让同一版本在不同设备上产生不同 schema。直接下发旧二进制可能无法理解新 schema，甚至破坏数据。

控制：旧 migration 不可变、CI 校验 fingerprint；每次发布测试 N-1 数据升级。故障只发布更高 build 的前向修复，不执行 destructive down migration。

### 5.5 超大数据和资源耗尽

整月流水和六个月分析当前会把明细读取到 JS；搜索使用前置通配 LIKE。大量记录或长查询可能造成启动变慢、内存压力和拒绝服务。

控制：输入长度继续在领域层校验；流水使用 cursor 分页，统计逐步移到 SQL 聚合；建立 10k/100k 记录性能基线和查询计划测试。这是 P1，除非实测已导致崩溃。

## 6. 数据生命周期

| 数据          | 当前来源       | 当前存储                      | 对外传输                       | 当前删除           | 第一版要求                             |
| ------------- | -------------- | ----------------------------- | ------------------------------ | ------------------ | -------------------------------------- |
| 已确认交易    | 手动/文字/语音 | SQLite                        | 无                             | 软删除，可恢复     | 导出、备份、永久删除、删除全部         |
| 待确认交易    | 用户显式暂存   | SQLite                        | 无                             | 可软删除           | 批量处理及删除范围说明                 |
| 原始文字/转写 | 智能记账       | 留存开启时写入交易与 feedback | 无                             | 设置关闭即事务清除 | 删除全部仍需覆盖；真机隐私验收         |
| 原始音频      | 系统语音       | App 不保存                    | 可能由系统服务处理，需明确同意 | 不适用             | 保持不落盘及联网显式选择               |
| 规则与反馈    | 用户纠正       | SQLite                        | 无                             | 部分规则可删除     | 删除全部覆盖；学习关闭不新增           |
| 回收站        | 软删除交易     | SQLite，无期限                | 无                             | 可恢复，无清空入口 | 明示期限或用户永久删除，不静默无限保留 |
| CSV/备份      | 尚未实现       | 尚未实现                      | 用户主动选择文件目标           | 尚未实现           | 警示明文风险、版本/校验、原子恢复      |

任何新表、缓存、日志、备份或第三方 SDK 上线前必须更新本表并回答“谁能读、保存多久、如何删除、删除失败如何恢复”。

## 7. 禁止事项

- 不生成、提交或打印生产 keystore、证书、密码和 API key。
- 不把 Debug 签名生产 ID 的 APK 对外称为生产 Release。
- 不记录完整账本、语音转写、SQL 参数、token 或原始异常 cause。
- 不自动联网语音、不预申请无关权限、不上传全部通知。
- 不使用破解、抓包或私有数据库读取支付数据。
- 不做数据库 down migration，不静默重建空库掩盖损坏。
- 不因“成熟”引入账号、云同步、广告或大模型，除非 PRD 后续阶段明确授权。
